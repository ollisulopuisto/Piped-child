# Golden DASH comparison

`dashutils_expected.mpd` was generated by running the web client's own
`src/utils/DashUtils.js` (unmodified, under node with fast-xml-parser@4) on
`dashutils_input.json` — a synthetic adaptive-format set shaped like a healthy
`/streams` response (two audio itags, two video itags, one muxed 360p and one
storyboard entry that must both be excluded).

Regenerate with:

```
npm install fast-xml-parser@4 --no-save   # at repo root
node clients/contracts/golden/generate-dash-golden.mjs
```

`core-player`'s `DashUtilsGoldenTest` parses both this golden and the Kotlin
port's output through Media3's `DashManifestParser` and asserts structural
equality (adaptation sets, representation ids/codecs/bandwidths/dimensions/
base URLs), identical segment ranges, and an identical MPD envelope.

Known, documented deviation: the Kotlin port omits `AdaptationSet id` because
Media3 requires it to be numeric (DASH spec: unsignedInt) while the JS emits
the string `audioTrackId`. The golden input therefore uses null track ids,
matching healthy YouTube responses; the per-language track separation is
covered by its own test in `DashManifestGeneratorTest`.
