# API contracts — Piped instance endpoints

Derived from the Piped OpenAPI spec (TeamPiped/OpenAPI), the Piped-child
frontend source (src/composables, src/components), and live verification
2026-11-18 (see ../fixtures). Both client implementations (Kotlin, Swift)
must parse every fixture in ../fixtures and pass the shared scenario tests.

Base URL: user-configured instance, bare paths (no `/api/v1` prefix).

## Common rules

- Auth: `Authorization: <token>` header, token from POST /login. Scoped to
  the issuing instance; never sent elsewhere.
- Errors: non-2xx with JSON body `{"error": string, "message": string}`.
  Clients must map: network down, instance 5xx, extraction failure (500 with
  LOGIN_REQUIRED/bot message), 401 auth failure, 404 video unavailable,
  429 rate limit, malformed body — per spec §10.
- Pagination: responses carrying `nextpage` (string) are continued via the
  matching `/nextpage/*` endpoint with the original query plus
  `nextpage=<token>`.
- All timestamps/durations: seconds. URLs may point at the instance proxy.

## Discovery

GET /trending?region=XX → array of StreamItem.
GET /search?q=&filter=videos|channels|playlists|music_songs|music_videos|music_albums|music_artists
  → `{"items": [SearchItem...], "nextpage": string, "suggestion": string?,
  "corrected": bool?}`. SearchItem.type: stream | channel | playlist.
GET /nextpage/search (same params + nextpage) → same shape.
GET /opensearch/suggestions?query= → `["query", ["suggestion", ...]]`.

StreamItem: url (`/watch?v=ID`), type "stream", title, thumbnail, uploaderName,
uploaderUrl, uploaderAvatar, uploadedDate, uploaded (epoch ms, may be -1),
duration (s, -1 for live), views, uploaderVerified, shortDescription,
isShort.

## Playback

GET /streams/{videoId} → StreamsResponse:
- dash: string|null (MPD URL), hls: string|null (m3u8 URL), livestream: bool
- videoStreams[] / audioStreams[]: url, format, quality, codec, mimeType,
  itag, bitrate, width, height, fps, videoOnly, initStart/End, indexStart/End,
  audioTrackId/Locale/Name/Type, contentLength
- subtitles[]: name, code, url, mimeType, autoGenerated
- chapters[]: title, start (s), image
- previewFrames[]: urls, totalCount, durationPerFrame, framesPerPageX/Y
- relatedStreams[]: StreamItem
- title, description, uploadDate, uploader*, duration, views, likes,
  dislikes, visibility, category, license, lbryId, proxyPrefix
- 500 with `{"error","message"}` when extraction fails (bot-block) — see
  fixtures/streams_error_login_required.json. THIS IS A NORMAL STATE.

iOS playback fallback order: hls → progressive (videoOnly=false) MP4 →
actionable error. Android: dash → generated/local HLS → progressive → error.

## Social/metadata

GET /comments/{videoId} → `{"comments":[Comment...], "nextpage": string,
"commentCount": number, "disabled": bool}`.
GET /sponsors/{videoId}?category=["sponsor",...] → `{"segments":[{segment:
[start,end], category, UUID, videoDuration, actionType, description, locked,
votes}], ...}` or `{}`.
GET /dearrow?videoIds=a,b,c → map videoId → `{titles:[{title, original,
votes, locked, UUID}], thumbnails:[{timestamp, original, votes, locked,
UUID}]}`.
GET /channel/{id} (aliases /c/{name}, /user/{name}) → channel + relatedStreams
+ nextpage. GET /channels/tabs, GET /nextpage/channel/{id}.
GET /config → instance metadata (used for validation display).

## Account (token in Authorization header)

POST /login `{username, password}` → `{token}` (or error body).
POST /register, POST /logout, POST /user/delete.
GET /feed?authToken= → prefer header variant GET /feed with Authorization.
GET /subscriptions, POST /subscribe `{channelId}`, POST /unsubscribe,
GET /subscribed?channelId=.
GET /user/playlists → [{id, name, shortDescription, thumbnail, videos}].
POST /user/playlists/create `{name}`; /delete `{playlistId}`; /rename
`{playlistId, newName}`; /description; POST /user/playlists/add
`{playlistId, videoIds:[...]}`; POST /user/playlists/remove
`{playlistId, index}`.
GET /playlists/{id} → playlist + relatedStreams + nextpage;
GET /nextpage/playlists/{id}.

Unauthenticated variants (local subscriptions): POST
/subscriptions/unauthenticated `{channels:[...]}`,
GET /feed/unauthenticated?channels=..., RSS variants — used only when the
user has no account; parity with web behavior.
